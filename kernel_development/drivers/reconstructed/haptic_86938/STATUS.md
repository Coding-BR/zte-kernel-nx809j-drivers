## Historical revalidation 2026-11-03 — LED-child sysfs teardown (candidate 116F401D)

Candidate `116f401d4f5d708f93d4c9cce26f516d1e0c0ac4a37c44aace2b0d6d453da051` statically closes the LED/sysfs callback window recorded as HAP-LED-01 and HAP-SYSFS-01/02/03. Probe registers both attribute groups on the LED child device. `aw_remove` sets the shutdown gate, calls `led_classdev_unregister` while state is valid, and only then drains firmware callbacks, work and timers or releases device resources. In the pinned kernel, LED unregister invokes `device_unregister`; `device_del` removes the child kobject; sysfs removal recursively deactivates the attribute nodes and waits for active kernfs operations to drain. The worker also reads a distinct global, `tiktap_mix_flag`; the two flags are identified separately by their ELF relocations.

Stock ioctl `0x5212` submits `richtap_stop_work` with `queue_work_on` and returns from the ioctl path. Therefore the userspace stop call does not prove that the detached FIFO producer has exited before the kernel stop work runs or before `tiktap_stop` returns. This is a possible cross-boundary ordering window, not a reproduced race or confirmed post-stop FIFO write. The candidate remains uninstalled and no path-specific stop/worker overlap was captured.

## Current C6 nested FIFO retry while holding the IRQ/stop mutex — 2026-11-03

Static disassembly review found that `richtap_rtp_work` holds `haptic_irq_stop_lock` while calling `richtap_update_fifo_data`. In one retry path, the helper can request three 1 ms sleeps while the mutex remains held, adding up to 3 ms of requested sleep plus scheduler time to that mutex hold. This differs from the worker's outer FIFO polling sleep, which occurs after releasing the mutex. The mutex is sleepable, so this is not a sleep-in-atomic error. Although `irq_handle` uses the same mutex, its arming gate returns before locking while RTP startup is active; this review therefore does not claim an IRQ stall. No device timing was measured.

Stock also retries with `usleep_range_state`; the candidate's surrounding mutex is a hardening deviation. Both FIFO functions remain `candidate_under_static_validation`, semantic equivalence and runtime latency are unverified, no source/map status changed, and the driver remains **INCOMPLETE**.
