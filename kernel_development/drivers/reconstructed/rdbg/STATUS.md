# rdbg — offline static reconstruction verified; full validation incomplete

Status: STATIC_VERIFIED_OFFLINE; full semantic and hardware validation remains incomplete.

- All 8 stock functions are mapped to C candidate sources. Their individual status and evidence are recorded in `reconstruction_map.json` and the versioned attestations.
- The 2026-11-03 [platform-driver lifetime audit](../../../../reverse_engineering/validation/reconstructed/rdbg/attestation/platform_driver_lifecycle_audit_20261103/README.md) confirms stock-matching cleanup hazards: later init failures and normal unload omit `platform_driver_unregister`; the module-init failure path frees the module without calling its exit routine; cleanup unregisters one character-device minor after reserving 16; and a failed platform-driver registration returns without freeing the clients array. These are static findings in the stock behavior and exact candidate, not reconstruction mismatches. Runtime failure was not reproduced; keep the candidate offline-only.
- The 2026-11-03 [threaded IRQ lifetime audit](../../../../reverse_engineering/validation/reconstructed/rdbg/attestation/irq_lifetime_audit_20261103/README.md) confirms that `rdbg_open` requests a non-shared threaded IRQ but does not free it on SMQ initialization failure; `rdbg_release` also leaves it registered after resetting the open state and destroying the SMQ mutex. The handler remains associated with the client completion, and a later open can fail with `-EBUSY`. This is stock-matching static evidence, not a runtime reproduction; keep the candidate offline-only.
- The 2026-11-03 [SMQ read-concurrency audit](../../../../reverse_engineering/validation/reconstructed/rdbg/attestation/smq_read_concurrency_audit_20261103/README.md) finds that concurrent `read()` calls sharing the one allowed character-device open are not serialized by the pinned VFS, while the consumer SMQ lock pointer is null. Multiple pending IRQ completions can therefore let readers race on the sent/free indices. The host write path has mutex/barrier evidence, but the remote firmware's matching memory-order protocol is not established here. Static finding only; no runtime race was reproduced.
